* Purpose

This document preserves completed implementation history, parked decisions,
external references, and frozen material for =guixpc=.  It is reference
evidence, not an active roadmap or authorization for new work.

* Accepted implementation history

This was the outcome-based plan used to develop =guixpc=.  EXWM remains the
accepted desktop direction.  The target was a predictable, coherent
workstation with clear ownership, useful recovery paths, safe maintenance, a
practical Scheme learning environment, and small Lisp-native tools where they
improve daily use.  It was not a framework-adoption, language-collection, or
operating-system research plan.

Each slice is separately authorized.  C0 is closed at published checkpoint
=e8ce8b2=.  C1 is closed at published implementation checkpoint =57969d1= and
was accepted live on 2026-07-21.  C2 is closed at published implementation
checkpoint =13981e9= and was accepted live on 2026-07-22.  C3 is closed at
published documentation checkpoint =75b0726= and was accepted live on

** C1 — Make EXWM input, cancellation, and launching predictable

- Result: context-aware escape/cancel behavior works across regions,
  minibuffers, transient helpers, Evil, terminals, REPLs, and EXWM; sending the
  next key to an X client remains explicit; launcher behavior is consistent
  and discoverable.  Existing Super bindings remain, while the physical
  34-key keyboard's Ctrl+Alt layer is the canonical action vocabulary and
  agrees with the macOS AeroSpace implementation.  The existing MSI/NixOS
  configuration is a partial reference whose parity gaps are recorded rather
  than copied into GuixPC.  GuixPC owns exactly five workspaces: physical
  =Q/W/E/R/T= select them and Shift moves to them; =Y/U/I/O/P= do not create
  extra workspaces.  The Ctrl+Alt aliases are deliberately EXWM-global,
  including inside Emacs buffers: the physical WM layer controls the whole
  session and therefore occupies those corresponding =C-M= editing chords.
- Reference: the exact physical source is
  =yivu-corne-v4/validation/2026-07-20-lp-34-rgb-off-left-final/stock-layout.vil=
  at content digest =afe26819eef3= (from =git hash-object=).  Cross-host
  semantics were compared with =nixos-macos/darwin/modules/aerospace.nix= at
  commit =b2ea774= and =nixos-dotfiles/config/hypr/hyprland.lua= at commit
  =73e2bd8=.  AeroSpace is the complete semantic reference.  NixOS currently
  differs for browser/Code, Shift+move, fullscreen, and reload; those are
  cross-host parity debts, not GuixPC C1 work.  Neither reference repository is
  modified by this slice.
- Boundary: hand-test the cancel/pass-through and 34-key matrices.  Do not
  rewrite completion, tabs, or the window manager; do not add launcher history,
  ranking, or a separate desktop-entry database.  C1 covers launch Terminal,
  Emacs home, Code/VSCodium, browser, files, and app picker; focus and move;
  close, fullscreen, and reload; and workspace switch/move 1--5.  Shift is
  explicit for every move action.  Float/tile, layout, and resize belong to C2,
  while clipboard and screenshot actions belong to C3.
- State: the interaction matrix was accepted live on 2026-07-21 at published
  checkpoint =57969d1=, with the same Emacs process healthy through activation
  and physical testing.  The tested physical positions were =N= Apps;
  =H/J/K/L= focus and Shift/Move; =S= Emacs; =A/D/F/G=
  Terminal/Code/browser/files; =;= fullscreen; =Z= close; and =.= reload.
  Escape, =C-g=, and literal =C-q C-g= also passed.  The original acceptance
  test exercised an on-demand tenth workspace; the user subsequently narrowed
  the intended contract to exactly five on 2026-07-21.  Follow-up checkpoint
  =0d3ced7= removes workspace 6--10 actions.  A clean reboot confirmed the
  configured, policy, and live counts at exactly =5/5/5=; the corrected source
  passed 90/90 isolated Emacs tests and both connected Lisp backend checks.

** C2 — Normalize EXWM windows, helpers, dialogs, and recovery

- Result: Help and documentation, Dired/Ibuffer/Treemacs/Magit, compilation
  and diagnostics, warnings and backtraces, Geiser/SLY helpers, transients, X
  dialogs, fullscreen windows, startup, and winner restoration have deliberate
  placement and focus behavior.  The reserved 34-key float/tile, layout, and
  resize actions have deliberate EXWM behavior.  Add one recovery command only
  if the tests demonstrate a real need.
- Boundary: the representative window matrix, reserved-action matrix, and
  recovery hand test pass.  Do not introduce Beframe, Bufferlo, tab workspaces,
  or a master-stack rewrite.
- Deliberate matrix: Treemacs remains left; ordinary utilities and REPLs use
  right slot 0; Help/Helpful/Info/Man/Apropos and Lisp documentation use right
  slot 1; compilation, Flycheck, warnings, backtraces, and active debuggers use
  bottom slot 0; completions and Transient use bottom slot 1 without replacing
  diagnostics.  Passive output does not steal source focus.  Explicit helper
  commands retain their existing focus behavior.
- Reserved physical actions: =X= toggles an X client between tiled and
  floating; =C= restores the existing master/stack layout; =V= and =B= resize
  narrower and wider.  Layout normalization preserves side helpers and asks a
  floating client to tile first.  Clipboard and screenshot remain C3 work.
- Recovery policy: Winner continues to own Emacs layout undo/redo, dead EXWM
  frame records are pruned, and Winner restoration cannot leave the full-frame
  toggle stale.  EXWM's reviewed default continues to float and focus X
  transient, fixed-size, utility, and dialog clients.  No new recovery command
  was justified.
- Floating-frame policy: =fullscreen= is a workspace-only creation default and
  is retired after EXWM creates its five workspace frames.  Later floating X
  frames therefore honor the client's requested geometry; no arbitrary
  application or dialog size table is needed.
- State: closed and accepted live on 2026-07-22.  Checkpoints =0d3ced7= and
  =13981e9= are published and running after a clean reboot and source reload.
  The full live gate, 91/91 isolated tests, and both connected Lisp backends
  passed with exactly five workspaces.  Physical =X/C/V/B= behavior, side-help
  normalization, Winner/full-frame recovery, and dialog focus restoration all
  passed.  Blueman's fixed-size About dialog exposed the inherited fullscreen
  default: it requested =424x367= but initially occupied =3440x1440=.  After
  the source fix was published and reloaded, a fresh dialog requested
  =424x367=, rendered at =444x394= around that client geometry, had no
  fullscreen state, received focus, and returned focus to its live manager
  parent when dismissed with its native Escape path.  Emacs remained PID 480.
- Known boundary: =sk/exwm-close-current= was not accepted as a GTK-modal

** C4 — Simplify and accept the existing Org workflow

- Result: capture, clarification, refile, agenda, daily review, and weekly
  review each have one obvious command and a short help surface.  Redundancy is
  removed only when it is confusing, completed-task handling is decided
  explicitly, and normal editing is free of Org lint failures.
- Accepted command surface:
  - =SPC n c/i/a/d/w/h= are the concise Emacs-buffer routes for capture,
    Inbox clarification, agenda, daily review, weekly review, and workflow
    help.
  - =C-c j= and every existing =C-c n= route are retained for non-leader use
    from EXWM application buffers in line mode.  Existing =C-c n d/w= keep
    their original raw daily/weekly-note behavior; =C-c n r= remains daily
    review, and =C-c n W/h= add weekly review and help.
  - The remaining useful =SPC n= note, search, TODO, and refresh commands stay
    available.  Only the duplicate =SPC n r= route is retired.
  - In Org buffers, =SPC m r= directly refiles.  The nested duplicate
    =SPC m s r= is retired; both existing manual archive routes remain.
- Capture and review contract: the central =Inbox.org= is the canonical
  general capture and clarification queue.  Direct task capture remains
  available, while daily capture is named =Daily inbox= and targets the daily
  =Inbox= heading.  Daily and weekly review open the corresponding note beside
  the matching agenda dashboard through the shared window policy.
- Completion and archive contract: changing an item to =DONE= or =COMPLETED=
  leaves it in place.  No TODO-state hook automatically refiles or archives
  anything.  A manual archive action moves the subtree into central
  =Archive.org= under a source-file heading; that archive is excluded from
  active agenda discovery.
- File-generation contract: external daily/weekly templates are complete Org
  documents.  Future notes receive title, date, startup, category, and filetag
  keywords exactly once; the source fallbacks mirror the accepted templates.
- Existing writing-width contract: =sk-core.el= already sets default
  =fill-column= to 100, while =sk-org.el= centers a 100-column visual fill with
  soft visual wrapping.  C4 preserves and explicitly accepts that pairing
  without enabling automatic hard wrapping.
- Acceptance: isolated synthetic-data tests cover the command surface,
  generated-note lint, Inbox matching and reveal, review layout, DONE and
  COMPLETED retention, and actual central archiving.  A focused Home build
  passes without installation.  After a fresh Emacs/EXWM start, the read-only
  hand pass covers workflow help, Inbox clarification, both review layouts,
  and opening and cancelling the direct refile prompt.  Capture, actual
  refiling, completion, and archiving against personal notes remain outside
  this acceptance pass because they belong to the separate personal-data edit
  gate.
- Boundary: do not replace the current Org system, add automatic DONE handling,
  alter EXWM-global keys, or edit personal Org data during the source pass.
  The 17 low-severity findings found in existing personal notes are a separate
  explicit data-edit gate.
- State: closed and accepted live on 2026-07-25 at published implementation
  checkpoint =27053c8=.  The focused non-activating Home build passed and
  returned the existing generation-52 result
  =/gnu/store/lr4dhsy2l8y2mfmf96rfn23pmb22g3nl-home=, as expected because

backlogs.  An imported idea still needs a local problem, a bounded result, and
explicit slice authorization.

* Parked decisions and revisit signals

The following work is deliberately parked.  It is not a dependency for
C0--C20 and may not be used as a blocker.  The signal beside each item is what
to look for before discussing it again.

- *Leaving EXWM or adopting RDE/Sway as the desktop:* revisit only if an
  accepted daily workflow cannot be made reliable in EXWM, EXWM becomes
  unmaintainable, or a concrete security requirement cannot be met.
- *Migrating from Xorg to XLibre:* keep the packaging reference, but revisit
  only for a reproducible Xorg defect or security need and a mature,
  reviewable Guix package and rollback path.
- *General startup optimization:* revisit for repeated user-visible boot or
  EXWM latency, hangs, or interaction loss.  A benchmark opportunity alone is
  not a reason.
- *Qt normalization:* revisit when a real daily-use Qt application exists and
  visibly violates the accepted theme tokens.
- *New Lisp dialects or broad Emacs application suites:* revisit only for a
  concrete project, curriculum, or recurring workflow that the current tools
  cannot serve.
- *Large workspace, completion, tab, or launcher frameworks:* revisit only
  after a named EXWM friction survives the focused C1/C2 approach.
- *Kernel, IRQ, HPET/TSC, USB-keyboard, or other hardware experiments:* revisit
  for a repeatable disruptive symptom such as crashes, data loss, material
  latency, or device failure, with evidence that points to that layer.
- *P5.2b, D1--D5 descendants, custom GRUB work, and direct System-generation
  deletion:* are archived on the immutable experiment branch.  Revisit only if
  disk pressure remains after the supported C10 path and a simpler supported
  recovery route is unavailable.
- *Backup implementation, repartitioning, migration, or assigning the second
  SSD:* revisit when important local-only data grows, affordable storage
  becomes available, or the accepted risk posture changes.
- *RSS, mail, Ledger, Calibre, and Studium-style environment expansion:*
  revisit one application at a time when a recurring real workflow appears.
- *Replacing BlueZ, PipeWire, WirePlumber, or NetworkManager:* revisit only if
  an upstream daemon cannot meet a concrete requirement; C13--C15 build small
  Lisp-native control surfaces over the existing services.
- *A resident health daemon, database, telemetry system, or Guix framework:*
  revisit only when the read-only, on-demand C6 design demonstrably cannot
  answer an accepted operational question.
