* Purpose

C5 gives the existing guixpc Home and XDG layout explicit ownership without
turning hygiene into a filesystem-management framework.  The companion
=scripts/home-xdg-audit.scm= is a read-only Guile program with a static
one-level manifest.

The program reads only:

- existence, type, owner, mode, link target, and reported file size;
- the direct children of =~=, =~/.config=, =~/.local=,
  =~/.local/share=, =~/.local/state=, and =~/.cache=.

It does not read file contents, follow personal directory trees, call Guix,
write state, delete or move paths, activate Home, or run garbage collection.
Each result is emitted as a quoted Scheme record so unusual filenames cannot
corrupt the report.

* Ownership classes

| Class | Meaning | Current policy |
|-------+---------+----------------|
| declarative | Guix Home, Guix profile, or repository-owned configuration | verify and keep |
| durable-synchronized | user data intended for the later private Org synchronization slice | keep untouched |
| durable-local | valuable machine-local data and application state | keep |
| secret | authentication or private trust material | keep private and outside cleanup |
| state-log | logs or state that belongs below XDG state | keep or propose a targeted migration |
| cache | reproducible or disposable acceleration data | keep while capacity is healthy |
| runtime | session-only authentication or coordination data | leave to its runtime owner |
| mixed | a directory containing more than one ownership class | require targeted handling |
| legacy | an older conventional location with no demonstrated current defect | review, never delete implicitly |
| unknown | no legitimate owner established | exact review candidate |

** Keep as cache

The large cache trees are not a capacity problem:

- Guix: 1.3 GiB, chiefly channel checkouts;
- Chromium: 923 MiB;
- Emacs: 103 MiB, including the active profile-keyed native cache.

Removing them would affect the roomy =/home= filesystem, not the separate root
filesystem.  C5 therefore adds no cache purge or schedule.

* Guix estimator incident

During the inventory, the documented retention =estimate= action called
Guix's =find-roots=.  Guix automatically removed 26 auto-root symlinks whose
profile-cache targets were already absent.

No store item, generation, configuration, or user data was deleted.  Current
and booted System still match, Home generation 52 remains active, and the
repository is unchanged.  Nevertheless, removing dangling root metadata is a
mutation, so the action is not strictly read-only.

C5 will not call that estimator again.  Correcting its contract is parked for
C10 and must not revive the frozen pruning experiment.

* Running the audit

From the repository root:

#+begin_src sh
guile --no-auto-compile -s scripts/home-xdg-audit.scm
#+end_src

The command exits nonzero only for an ownership, type, permission, or expected
link-target failure.  Known candidates and newly observed direct children
produce =review= records without changing the filesystem.

The initial 2026-07-25 live run reported =105 pass=, =10 review=, =0 fail=,
and =0 absent=.  No unclassified direct child was found.  The ten review
records were the two unknown files, =~/.clojure=, =~/.dbus=, =~/.emacs.d= as
one mixed tree, the Geiser history, =~/.ruff_cache=,
=~/.local/share/xorg=, =~/.cache/emacs=, and the legacy EXWM log.
